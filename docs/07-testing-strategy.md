# Virotrace — Testing Strategy

---

## 1. What is actually being tested

A bioinformatics pipeline has two independent failure modes, and conflating them is why many research
repos have tests that pass while the science is wrong:

| Failure mode | Looks like | Caught by |
|---|---|---|
| **Software defect** | Crash, wrong join, off-by-one slice, dropped rows | Unit, contract, integration tests |
| **Scientific defect** | Runs cleanly, produces a confident wrong number | Positive controls, negative controls, invariants, external plausibility |

The second is the dangerous one. A DRM caller that silently reports every uncovered position as
wild-type will never raise an exception; it will just produce a reassuringly low resistance
prevalence. So the suite is built around **controls and invariants**, with conventional unit tests as
the cheap foundation rather than the main event.

## 2. The pyramid

```
            ┌───────────────────────────────┐
            │ smoke: full dev-profile DAG   │  1 test, minutes, in CI
            ├───────────────────────────────┤
            │ regression: golden outputs    │  ~10
            ├───────────────────────────────┤
            │ integration: stage chains     │  ~20
            ├───────────────────────────────┤
            │ contract: schemas, coords     │  ~15
            ├───────────────────────────────┤
            │ unit: pure functions          │  ~80
            └───────────────────────────────┘
```

Target: **≤ 60 s for `make test` excluding the smoke test**, because a suite that is slow stops being
run. The smoke test runs in CI and on demand.

## 3. Fixtures

All fixtures are synthetic or public reference sequences — no real patient-derived data in the repo.

| Fixture | Contents | Used for |
|---|---|---|
| `toy_pol.fasta` | ~20 sequences derived from HXB2 with **deliberately planted** mutations at known positions, plus engineered defects: one short, one high-ambiguity, one frameshifted, one with an internal stop, one lab strain | QC rules, mutation extraction, end-to-end dev build |
| `positive_controls.tsv` | sequence ID → expected mutation list, expected drug class, expected interpretation level | DRM caller correctness |
| `hypermut_pair.fasta` | one sequence with APOBEC-context G→A editing applied, and its unedited parent | Hypermutation screen sensitivity **and** specificity |
| `subtype_refs_mini.fasta` | a handful of known-subtype references | Subtype calling recovers truth |
| `recombinant_synthetic.fasta` | a constructed A1/D recombinant with a known breakpoint position | Recombination screen |
| `metadata_toy.tsv` | rows exercising every schema edge: year-only date, missing admin1, unmapped country string, duplicate strain | Normalisation and validation |
| `wild_type_pol.fasta` | clean HXB2-like sequence, no DRMs | **Negative control** |

Fixtures are generated by `tests/fixtures/build_fixtures.py`, committed as outputs, and regenerating
them is a reviewed change — so a fixture never drifts to match a bug.

## 4. Scientific correctness tests

These are the tests that earn trust.

**Positive controls — DRM calling**
```python
@pytest.mark.parametrize("strain,expected", load_positive_controls())
def test_known_mutations_are_called(strain, expected, drm_caller):
    called = drm_caller.call(fixture_seq(strain))
    assert expected.mutations <= {m.label for m in called}
    assert expected.classes <= {m.drug_class for m in called}
```
Planted mutations spanning each class (an NRTI, an NNRTI, a PI, an INSTI mutation) must each be
recovered with the right class. Additionally, the Stanford HIVDB published validation datasets are
used out-of-band to check agreement on a larger sample before release.

**Negative control**
```python
def test_wild_type_yields_no_sdrm(drm_caller):
    assert [m for m in drm_caller.call(wild_type()) if m.is_sdrm] == []
```
A caller that finds resistance in wild type is worse than useless. This test is as important as the
positive controls and is routinely the one people forget.

**No-coverage must mean no-call, not wild-type**
```python
def test_uncovered_positions_are_no_call(drm_caller):
    seq = truncate_before(RT_CODON := 184)
    calls = drm_caller.call(seq)
    assert calls.status_at("RT", 184) == "no_call"
    assert "RT:M184" not in {m.position_label for m in calls}
```
This is the single highest-value test in the repo. It directly guards the silent-false-negative
failure mode described in §1.

**Hypermutation: sensitivity and specificity**
```python
def test_hypermut_flags_edited_and_spares_parent():
    edited, parent = hypermut_pair()
    assert screen(edited).flagged is True
    assert screen(parent).flagged is False
```

**Coordinate integrity**
```python
def test_gene_ranges_match_annotated_reference(hxb2_record, config):
    for gene, (start, end) in config.reference.genes.items():
        feat = find_cds(hxb2_record, gene)
        assert (feat.start + 1, feat.end) == (start, end)
        assert (end - start + 1) % 3 == 0
```
The docs claim coordinates; this test makes the claim falsifiable.

**Frame invariant**
```python
@given(seq=aligned_pol_sequences())
def test_retained_sequences_translate_cleanly(seq):
    aa = translate_codon_aware(seq)
    assert "*" not in aa[:-1]
```

**Subtype recovery and recombination detection** — reference sequences of known subtype must recover
their subtype; the synthetic recombinant must be flagged and its breakpoint located within a
configured tolerance of the construction point.

## 5. Invariant and property tests

Properties that must hold for *any* input, checked with Hypothesis:

| Invariant | Why it catches real bugs |
|---|---|
| `n_in == n_out + n_excluded + n_quarantined` at every stage | The commonest silent bug in a filtering pipeline is losing records with no ledger entry |
| Every excluded record has exactly one primary `qc_reason` | Prevents double-counting in the QC waterfall figure |
| Prevalence numerator ≤ denominator, and denominator ≤ class-covered count | Guards the per-class denominator logic |
| Wilson CI contains the point estimate; bounds within [0,1] | Catches interval-math slips |
| Subsampling is idempotent for a fixed seed | Determinism guarantee |
| Subsampling never returns more than `max_per_stratum` per stratum, nor drops a stratum below `min_per_stratum` when records exist | Stratification correctness |
| Mutation labels round-trip: parse(label) == (gene, position, aa) | Catches numbering-convention mixups |
| Gene-local numbering never exceeds the gene's protein length | Catches HXB2-vs-gene-local confusion, a classic HIV bug |
| All strains in `drm_table.tsv` exist in `metadata.final.tsv` | Referential integrity across the layer boundary |

The record-conservation invariant is worth running at every stage, not once: it is cheap and it is the
test most likely to catch a refactor that quietly drops rows.

## 6. Contract tests

- `metadata.valid.tsv` validates against the pandera schema; every enum field rejects an out-of-vocabulary
  value; required fields reject null.
- Schema version in the file header matches `config.schema_version`; a mismatch fails loudly.
- `drm_table.tsv` and `prevalence.tsv` column sets and dtypes are asserted, because the Auspice export
  and the report both join on them.
- Auspice output validates against the Auspice v2 JSON schema — catching export breakage without
  opening a browser.
- Config schema: known-bad configs (min > max, `admin1.enabled: true` forced, `min_stratum_n: 0` in a
  non-dev profile) must be rejected by `validate config`.

## 7. Integration and regression

**Integration** — stage chains on fixtures, in-process, no network:
`normalise → validate → qc → align` · `align → subtype → recombination → subsample` ·
`subsample → drm call → prevalence` · `subsample → tree → refine → traits` ·
`drm + phylo → export auspice`.

The last one matters most: it is the file contract between the two layers, the place a schema drift
would otherwise surface only at demo time.

**Regression / golden files** — committed expected outputs for the dev profile. Compared with
tolerance: exact for tables and ledgers, numeric tolerance for floats, and for trees a
**topology-aware comparison** (Robinson–Foulds distance, with support values compared separately)
rather than string equality on Newick, which changes with node ordering for identical topologies.

Refreshing a golden file requires `make refresh-golden` and the diff must be explained in the PR. An
unexplained golden refresh is how a regression gets blessed into the baseline.

## 8. Smoke test

One test runs the entire dev-profile DAG via Snakemake and asserts:
- exit code 0;
- every `rule all` output exists and is non-empty;
- the Auspice JSON validates and contains ≥1 DRM colouring;
- the report HTML contains the limitations section (the config cannot switch it off, and this test
  proves the code honours that);
- a provenance sidecar exists for every terminal output;
- rerunning produces identical checksums for deterministic outputs.

That last assertion is the reproducibility claim, tested rather than asserted in a README.

## 9. CI

```yaml
# .github/workflows/ci.yml  (shape)
jobs:
  lint:       ruff check · ruff format --check · mypy --strict src/virotrace
  test:       pytest tests/unit tests/contract tests/integration -q   # no network
  dag:        snakemake --dry-run --profile dev  +  --profile kenya   # DAG validity, no execution
  smoke:      pytest tests/smoke -q              # scheduled + on release branches
```

Rules: no network access in the default test job (fixture source adapter only); mypy strict on `src/`;
coverage reported with a floor on `drm/`, `curate/qc.py`, and `prevalence.py` specifically, since
coverage percentage overall is a weak signal but coverage of those three modules is a strong one.

## 10. Manual validation checklist (pre-publication)

Automated tests cannot cover judgement. Before publishing a build:

- [ ] QC waterfall reviewed — is the excluded fraction plausible, and is any single rule excluding a surprising share?
- [ ] Subtype distribution compared against published Kenyan estimates; gross mismatch investigated as a probable bug.
- [ ] DRM prevalence magnitude compared against published regional estimates; order-of-magnitude disagreement investigated.
- [ ] Root-to-tip regression plot inspected by eye, not just by R² threshold.
- [ ] Estimated clock rate compared against the configured prior range; a rate far outside it is reported, not quietly accepted.
- [ ] Tree rerun at a second seed; major clade support qualitatively stable.
- [ ] Map legend states the fraction of records resolved only to country level.
- [ ] Every figure's denominator traceable to a table.
- [ ] Limitations section present, specific, and matching the methods actually used.
- [ ] Clinical-use disclaimer present in README, report, and Auspice description.
